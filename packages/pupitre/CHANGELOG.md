# Changelog

## 1.1.1 (2026-10-14)

### Changed
- Release: `@rikology/pupitre`, `-react` and `-ui` move lockstep to `1.1.1` (patch; sibling ranges stay `^1.1.0`, `catalogVersion` stays `1.1`).

### Fixed
- Widgets: `.canView(ctx, record?)` now receives the page record on resource edit/view pages (page props and the widget data/action endpoint). `loginHistoryWidget()` uses it, so users without `viewLoginHistory` no longer get the widget whose deferred load 403'd, looped on redirect-back, and left a "Forbidden" toast on the next page.
- Authorization: record Edit/View tabs are shown only when the viewer has the `update`/`view` ability for that record; previously the Edit tab was always offered and led to a 403.
- Authorization: a forbidden GET whose redirect-back target is the request's own URL (e.g. an Inertia deferred-prop reload) no longer redirects back to itself until the browser gives up, leaving a stale "Forbidden" flash for the next page. Like the existing panel-home case, it answers 403 directly; Inertia requests get JSON `{ message }`, which `@rikology/pupitre-react` shows as a "Forbidden" toast on the current page instead of Inertia's HTML error dialog.

## 1.1.0 (2026-10-14)

### Changed
- Release: `@rikology/pupitre`, `-react` and `-ui` move lockstep to `1.1.0` (`-react`/`-ui` now require `^1.1.0` of their siblings); `catalogVersion` is `1.1` (same major, so 1.0 clients do not force-reload).
- Localization (breaking for strict comparisons): server `t()` no longer returns its input unchanged. It returns the readable, interpolated English text followed by invisible signed translation metadata, so `t('Title') === 'Title'` is false. Resolve with `resolveTranslations()` / `stripTranslationMarkers()` before strict comparison, string transformation or delivery outside Pupitre responses, and use `captureTranslation()` / `restoreTranslation()` to persist translation intent. `Error.message`, logs and regex/`includes` checks keep reading the English text.
- Tables: toggle/checkbox inline-edit cells display "Enabled"/"Disabled" instead of "On"/"Off"; Shield permission checkboxes show human labels ("View any", "View") instead of ability names.
- Tenancy: the default column tenancy scope binds the tenant id as a string so TEXT ownership columns match on SQLite (better-sqlite3 binds JS numbers as REAL); integer ownership columns keep comparing and filling as integers on SQLite and PostgreSQL.
- Tables: the first list tab is applied by default when no `tab` is requested (Filament semantics); the URL and `normalized.tab` only echo an explicit, valid choice. Hosts whose first tab carries a `where` now see that filter on first load.
- Infolists: `repeatableEntry` always sends its child labels (`entries`) to the client, so repeated rows show "Product" instead of `productName`.

### Added
- Number formats: number/money separators follow a number locale separate from the UI language. Panel `.numberLocale('id-ID')` sets the default and `.numberLocales([...])` the profile choices (`[]` hides them); users pick a "Number format" in their profile (session plus optional `users.number_locale` column via migration stub `1791800000024`, `auth.columns.numberLocale`). Resolution: user → session → panel → UI locale; exposed as `ctx.pupitre.numberLocale` (code that builds `ctx.pupitre` by hand must set it) and shared as `pupitre.numberLocale`. Applies to money/numeric columns, entries, summaries and numeric stat values.
- Compact numbers: `.compact()` on money/numeric table columns and text entries, and `stat(...).money(currency).compact()`, shorten values with the number locale's CLDR abbreviations (`105,9 jt`, `105.9M`) and deliver the full value as `title`. `textEntry().numeric()` formats numbers with the number locale; numeric stat values are now locale-formatted instead of shown raw.
- Localization: request-local English/Indonesian localization. Server `t(key, params?)` markers are resolved at every Pupitre response boundary (structured Inertia props including full-page/SSR visits, JSON actions/options/search/notifications, auth mail, CSV/progress output); plural `{ one, other, zero? }` messages and `{name}` interpolation; `defineConfig({ i18n })` host dictionaries and `definePlugin({ messages })` plugin dictionaries; localized VineJS messages with field labels (host Vine providers keep precedence for untranslated rules); panel `.locale(string)` / `.locales([...])`, user/session/Accept-Language resolution, profile language selector and an optional `locale` users-column migration stub; `locale` is a reserved page/resource slug. Record data is never translated. ADR-0023.
- Localization: persisted notifications and queued CSV headers store readable text plus translation intent and are translated at read/render time (survives `APP_KEY` rotation); `tools/i18n-check` (`npm run i18n:check`) enforces Indonesian coverage of every literal `t()` key in CI.
- Catalog extensions: `defineCatalogExtension()` / `mergeCatalogExtensions()` in `@rikology/pupitre/catalog` and `defineField()`, `defineColumn()`, `defineEntry()` factories with typed custom methods, inherited field methods, Zod-validated props, VineJS value validation, server formatting/dehydration and live/repeater/action-modal support; `definePlugin({ catalog })` and `page.catalogExtensions` metadata. Element `type` in specs is now an open string validated by the client registry. ADR-0024.
- Tables: `table.filter.queryBuilder(name).constraints([...])` with `qb.text/number/date/boolean/select/relationship` constraints (`qb.number(...).integer()` for integer columns), negation, AND-within/OR-between groups, strict allowlist validation (400 on malformed, fractional-for-integer, out-of-range or year-zero values), size caps, scope-safe OR wrapping and timezone-aware calendar comparisons across table data, summaries, groups, relation tables, table widgets and exports. ADR-0025.
- Tables: opt-in `.multiSort(max = 3)`, ordered `.defaultSort([...])` and URL `sort=title,-price` with deterministic qualified primary-key tiebreakers; existing single-sort links keep working and `sort=` clears defaults.
- Validation: public `compileValidator()` / `FormValidator` so plugins, commands and jobs can validate data with a form's VineJS rules.
- Authorization: opt-in panel `.strictAuthorization()` validates after panel/plugin resolution that every resource, nested resource and relation-manager related model has an explicit or discovered policy (`E_PUPITRE_MISSING_POLICY`), denies policy-less checks at runtime, and is reported by `pupitre:inspect`.
- Panels: `.environmentIndicator({ visible?, label?, color? })` shares an `environment` prop (shown outside production by default); `.impersonation({ canImpersonate?, canBeImpersonated?, redirectTo? })` with `actions.impersonate()` (fail-closed `impersonate` policy ability, scoped tenant lookup, actor MFA required, rotated sessions, leave endpoint, profile security mutations blocked while impersonating, `pupitre:impersonation:started|stopped` events); `.sessions({ history?, retentionDays? })` tracks hashed browser-session tokens per login method, revokes unknown/revoked sessions on the next request, records authentication history (failed logins never store unknown emails), adds profile session management (password/passkey-confirmed "log out other sessions") and the policy-protected `loginHistoryWidget()`; `pupitre:prune` applies session/history retention. Migration stubs 1791700000045/46.
- Navigation: `defineCluster(slug)` with `.label/.icon/.navigationGroup/.sort/.subNavigationPosition`, `resource.cluster()` and `page.cluster()`; clusters are discovered from their children, collapse to one authorized navigation entry, prefix child routes (tenancy URL mode and nested resources included), render sibling sub-navigation and breadcrumbs, and reject slug collisions at boot. `node ace make:cluster`.
- Widgets: `.component(name, loader?)` delivers loader data to host components; `.actions([...])` runs authorized, Vine-validated widget actions through the JSON action transport; radar and scatter chart types with typed loaders.
- Tables: model-free custom-data tables via `t.records()`, `t.recordKey()` and `t.resolveRecord()` with URL-backed validated search/sort/filter/pagination, count-free pagination, server-resolved row/header/bulk actions and definition-time rejection of Lucid-only features (ADR-0026); `authorizeAbility()` passes the resolved row to host abilities.
- Tables: opt-in saved views (`t.savedViews()`, `t.presetViews([tableView(name).query(...).columns(...).default()])`) for resource and relation-manager tables, scoped per user/panel/tenant/table with validated stored queries, per-user defaults, explicit column visibility and fail-closed `managePublicViews` for public views. Migration stub 1791700000044.
- Exports: `actions.export().formats(['csv', 'xlsx'])` with a dependency-free streaming XLSX writer (inline strings, typed cells, bold header, CSV formula-injection policy), persisted format metadata, locale-resolved headers and private queued downloads; queued CSV output now streams too.
- Forms: `s.repeater(...).table([s.tableColumn(label).width().alignment().markAsRequired()])` table repeaters (positional or derived headers, `E_PUPITRE_INVALID_REPEATER_TABLE`); rich editor `.mergeTags()`, `.mentions([mentionProvider(char).options()/.search()])` through the protected options endpoint with save-time forgery stripping, and Vine-validated `.customBlocks([richBlock(id)...])`; `renderRichContent()` and `textEntry.html()/.richContent()` render escaped merge values and block HTML.
- Plugin support: public `parseInZone()`/`toIsoInZone()` timezone helpers; custom and resource pages accept structural widget builders.
- Plugin support: public `panelRouteGroups()` (authenticated, tenant-resolved panel route groups for plugin endpoints) and storage/upload helpers `createPupitreStorage`, `consumeFormUploads`, `sniffUploadMime`, `isUploadMimeAllowed`, `DEFAULT_UPLOAD_MAX_BYTES`.

### Fixed
- Resource pages: header builtins are scoped to the page they act on. Collection actions (`create`, `export`, `import`, `attach`, `associate`) appear only on the list page; record actions (`edit`, `view`, `delete`, `restore`, `forceDelete`, `replicate`, `impersonate`) only on edit/view pages and never on the page they point to. View pages get an "Edit" action when an edit page exists (previously a self-referencing "View"); the create page no longer repeats the list's header actions. Custom header actions keep appearing on every page as before.
- Action modals: uploads inside action forms use the server-issued `uploadOwner` (resource/record context) and action validation passes the resource slug to owned-upload validation, so session-owned uploads in header-action forms validate.
- Forms: `.hidden()` closures compile to a correct negated visibility condition — boolean literals flip (`.hidden(() => true)` → `visible: false`), `&&`/`||` conditions negate via De Morgan, and `!get(x)` drops its `not` — instead of spreading `not: true` onto non-condition values (which produced an invalid `{"not":true}` spec, e.g. the media resource's hidden `path` upload). Lifted `.visible()`/`.hidden()` results that are not valid json-render visibility conditions now fall back to server evaluation.

### Fixed
- Schema cache: field actions (`prefixAction`/`suffixAction`/`hintAction`), page actions, select action links, option/upload URLs and other request-derived props are re-evaluated per request on cache hits; previously the first request's record, URL and authorization result could be served to later users and tenants in production.
- Actions: header actions (no record, not bulk) require `viewAny` before running, matching the action form endpoint; custom actions without `.can()` could otherwise run for users denied the resource. Form field actions on the create page (no record) authorize with `create`.
- Tenancy: host `.scope()`, `table.query()`, custom filter/tab and relationship scope callbacks are applied as one AND-grouped `WHERE` clause, so a top-level `orWhere`, `orHas`/`orDoesntHave` or an OR inside a model scope (`withScopes`/`apply`) can no longer widen results past the tenant predicate. Non-`WHERE` calls (`orderBy`, `preload`, `join`, `select`, `withCount`) still apply to the main query. Nested resources keep the parent constraint outside the host scope group.
- Tenancy: related models that are not panel resources but carry the ownership column are tenant-scoped in relationship options, relationship validation and inline option creation, matching relation managers.
- CSV: exported cells and headers starting with `=`, `+`, `-`, `@`, tab or carriage return are prefixed with `'` to prevent spreadsheet formula execution (sync, queued and failed-row CSVs). Numeric values are unchanged.
- Imports: CSV imports call `beforeSave` in the same lifecycle position as resource create/update.
- Exports: queued exports persist the export action name; progress and download recheck that action's current `.can()` grant and fail closed when it is missing. Exports queued before this change must be recreated.
- Return URLs: `X-Pupitre-Url` is validated by one helper for resource, relation-manager, page and export requests; relation managers previously used it unvalidated, and `/\host` forms are now rejected everywhere.
- Records: identifiers that PostgreSQL cannot parse for the primary-key type (e.g. `/activity/create` on a UUID resource) return 404 instead of 500 on record, relation-manager, nested-parent, upload and bulk lookups.
- Uploads: permanent deletes (destroy, force delete, bulk and relation-manager deletes) remove the record's file-upload objects after the transaction commits when no other row references them; soft deletes keep files and storage errors are logged without failing the delete. Reference checks are batched per field.
- Uploads: new optional `pupitre_uploads` table tracks uploaded keys until a resource, list-page modal, custom page or action-form submission consumes them (after validation, before the save handler). `node ace pupitre:prune-uploads --older-than=24h` removes abandoned uploads: it claims each row before deleting its object and skips, without consuming, file fields whose references it cannot check (relationship repeaters, custom pages, removed fields). Run `node ace pupitre:install` and `node ace migration:run` to enable it; without the table uploads keep working and the command exits with an error.
- Queued bulk actions validate their form in the request, so field errors reach the action modal before anything is enqueued.
- Tables: image URL resolution is memoized per page and resolved concurrently instead of one storage `exists` round-trip per cell.
- Tests: the PostgreSQL suite passes (relation fixtures no longer replay DDL); c8 enforces 85% line coverage on `src/compiler`, `src/query` and `src/authz`.
